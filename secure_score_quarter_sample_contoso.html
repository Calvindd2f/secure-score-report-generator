Remediation Playbook

Contoso Holdings Ltd 2026-05-13
Identity and Access Controls

Identity controls should be treated as the first remediation workstream. These actions reduce the probability of account compromise and limit the blast radius when credentials are exposed.

1. Require MFA for all users via Conditional Access
Critical Licensed
Action
Create a Conditional Access policy requiring MFA for all users and all cloud apps. Exclude only approved emergency access accounts.
Implementation Notes
Pilot with IT and power users first. Confirm authentication methods registration before wider enforcement.
Validation
Review sign-in logs and confirm MFA claims are present for standard and privileged users.
2. Block legacy authentication protocols
Critical Licensed
Action
Block legacy clients including IMAP, POP, SMTP AUTH, and Basic Authentication through Conditional Access and Exchange Online configuration.
Implementation Notes
Query sign-in logs for legacy client usage before enforcement. Replace unsupported mail clients or service integrations.
Validation
Confirm legacy client sign-ins are blocked and no active mailbox workflows depend on them.
3. Configure Privileged Identity Management
High Licensed
Action
Move privileged Entra roles to eligible assignment and require just-in-time activation with MFA, justification, and approval where appropriate.
Implementation Notes
Start with Global Administrator, Privileged Role Administrator, Exchange Administrator, SharePoint Administrator, and Security Administrator.
Validation
Confirm no unnecessary permanent privileged assignments remain outside break-glass scope.
4. Separate admin accounts from daily-use accounts
High Licensed
Action
Create dedicated administrative accounts for privileged work and remove admin roles from standard user accounts.
Implementation Notes
Restrict admin accounts from email, Teams, and general browsing. Apply stronger CA requirements to privileged accounts.
Validation
Export privileged role assignments and verify no standard productivity accounts retain admin roles.
5. Enable Self-Service Password Reset and Password Protection
Medium Licensed
Action
Enable SSPR for all users and deploy password protection for weak, leaked, or banned password patterns.
Implementation Notes
Require two registration methods. Enable writeback for hybrid users where required.
Validation
Confirm registration completion, password reset success, and banned password enforcement.

Remediation Playbook

Contoso Holdings Ltd 2026-05-13
Endpoint, Data Protection and Application Controls

Once identity enforcement is stable, the next workstream should close device, data, and application governance gaps. These controls reduce unmanaged access, data leakage, weak auditability, and risky third-party app exposure.

6. Enrol devices in Microsoft Intune MDM
High Licensed
Action
Enrol Windows, macOS, iOS, and Android devices into Intune and enforce baseline compliance policies.
Implementation Notes
Define compliance rules for encryption, OS version, antivirus, firewall, and device risk.
Validation
Confirm devices appear as compliant and block unmanaged access using Conditional Access.
7. Enable Microsoft Defender for Endpoint Plan 2
High Licensed
Action
Onboard all supported endpoints into Defender for Endpoint and enable core EDR, antivirus, and attack surface reduction controls.
Implementation Notes
Deploy ASR rules in audit mode before enforcement. Tune exclusions with care and owner approval.
Validation
Confirm onboarding status, sensor health, antivirus state, and alert generation from test devices.
8. Create DLP policies for SharePoint and OneDrive
High Licensed
Action
Create DLP policies targeting sensitive information types such as financial, identity, HR, and customer data.
Implementation Notes
Start in simulation mode. Review matches, tune false positives, then enable user notifications.
Validation
Test upload, sharing, and external transfer scenarios using controlled sample data.
9. Enable audit log search and retention in Microsoft Purview
Medium Licensed
Action
Confirm unified audit logging is enabled and configure retention aligned to incident response and compliance requirements.
Implementation Notes
Create alerting for bulk downloads, external sharing, privilege changes, and suspicious mailbox actions.
Validation
Perform known test activities and confirm events are searchable within expected timeframes.
10. Review and restrict risky OAuth app permissions
High Licensed
Action
Review enterprise applications and consent grants. Remove unused apps and restrict high-risk permissions.
Implementation Notes
Pay close attention to Mail.ReadWrite, Files.ReadWrite.All, Directory.ReadWrite.All, and offline access scopes.
Validation
Confirm admin consent workflow is enabled and new high-impact permissions require approval.

Methodology and Disclaimer

Contoso Holdings Ltd 2026-05-13
Assessment Methodology

This report is based on Microsoft Secure Score data, tenant configuration observations, and available Microsoft 365 security control signals at the time of generation. The assessment reviews enabled controls, incomplete improvement actions, control categories, score movement, and prioritised remediation opportunities.

Secure Score is used as a directional benchmark for Microsoft 365 security maturity. It should be interpreted alongside operational context, licensing, business requirements, exception handling, and user impact.

Scoring Interpretation
80-100: Strong Position
Core Microsoft 365 security controls are mature, consistently enforced, and actively monitored.
65-79: Improving Position
Security foundation is mostly in place, with remaining medium or high-value controls requiring completion.
40-64: Significant Gaps
Multiple high-value controls remain incomplete. Remediation should be treated as a managed workstream.
0-39: High Exposure
Foundational protections are missing or inconsistently configured. Immediate remediation is recommended.
Assumptions and Scope

The report reflects the Microsoft 365 tenant state available at the time of collection. It does not include manual penetration testing, endpoint forensic review, source code review, identity compromise assessment, firewall review, or third-party SaaS configuration review unless separately stated.

Some Secure Score recommendations may require additional licensing, staged rollout, change approval, communications, pilot testing, or exception handling before enforcement.

Recommended remediation sequencing is based on risk reduction and operational practicality. Identity and privileged access controls are prioritised first because they provide the largest reduction in compromise likelihood and tenant-wide blast radius.
